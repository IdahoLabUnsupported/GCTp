# Complete Recreation Prompt: Interactive Comparison Matrix Generator

## Overview
Create a self-contained HTML artifact that generates an interactive, multi-category comparison matrix for any topic with comprehensive citations. The artifact must be a single HTML file with embedded CSS and JavaScript.

---

## Initial User Interaction Flow

When the user requests a comparison matrix for a topic, ask:
1. **Topic confirmation**: "I'll create a comprehensive comparison matrix for [TOPIC]. To ensure maximum value..."
2. **Scope**: "How many items should I include? (Recommended: 50-100)"
3. **Focus areas**: "Are there specific aspects or features to emphasize?"
4. **Categories**: "Should I determine optimal groupings, or do you have preferred categories?"

After gathering requirements, research thoroughly and build the complete artifact.

### Core Functions Required

#### 1. Column Filtering Logic
```javascript
function shouldIncludeColumn(columnIndex, categoryTools) {
    const values = categoryTools.map(tool => tool[columnIndex]);
    const nonEmptyValues = values.filter(v => v !== 'N/A' && v !== '✗');
    return nonEmptyValues.length > 0;
}
```

#### 2. Global Source Management
```javascript
let globalSourceCounter = 1;
const globalSourceMap = {};

function getSourceRef(url) {
    if (!globalSourceMap[url]) {
        globalSourceMap[url] = globalSourceCounter++;
    }
    return globalSourceMap[url];
}
```

#### 3. Table Rendering Logic

#### 4. Citation Assignment Per Cell - UPDATED
**CRITICAL LOGIC**: Map columns to appropriate source URLs and wrap values in spans:
```javascript
columnsToInclude.forEach((col, colIdx) => {
    const cell = tool[col.originalIndex];
    const td = document.createElement('td');
    
    // Map column index to source array index
    let sourceUrl = toolUrls[0] || '#'; // Default to main
    if (colIdx === 1) sourceUrl = toolUrls[1] || toolUrls[0];      // Cost/License
    else if (colIdx === 2) sourceUrl = toolUrls[2] || toolUrls[0]; // Platform
    else if (colIdx >= 3 && colIdx <= 5) sourceUrl = toolUrls[3] || toolUrls[0]; // Basic features
    else if (colIdx >= 6) sourceUrl = toolUrls[4] || toolUrls[0];  // Advanced features
    
    const refNum = getSourceRef(sourceUrl);
    
    // Track for local footnotes
    if (!localSourceRefs.find(ref => ref.num === refNum)) {
        localSourceRefs.push({ num: refNum, url: sourceUrl, tool: toolName });
    }
    
    // Add citation to cell - WRAP IN SPANS, NOT TD CLASSES
    if (col.originalIndex === 0) {
        td.className = 'tool-name';
        td.innerHTML = `${cell}<sup>${refNum}</sup>`;
    } else {
        const cellLower = typeof cell === 'string' ? cell.toLowerCase() : '';
        
        if (cell === '✓' || cellLower === 'yes' || cellLower === 'supported' || cellLower === 'available') {
            // Use span for styling, not td
            td.innerHTML = `<span class="yes">✓</span><sup>${refNum}</sup>`;
        } else if (cell === '✗' || cell === 'N/A' || cellLower === 'no' || cellLower === 'none') {
            td.className = 'no';
            td.innerHTML = `${cell}<sup>${refNum}</sup>`;
        } else if (cellLower.includes('via') || cellLower.includes('some') || 
                   cellLower.includes('limited') || cellLower.includes('basic') ||
                   cellLower.includes('partial')) {
            // Use span for styling, not td
            td.innerHTML = `<span class="partial">${cell}</span><sup>${refNum}</sup>`;
        } else {
            td.innerHTML = `${cell}<sup>${refNum}</sup>`;
        }
    }
});
```

**CRITICAL**: Wrap badge classes in `<span>` elements, NOT apply to `<td>` elements to prevent cell merging issues.

## Complete Rendering Pipeline

### 1. Initialize on DOMContentLoaded
```javascript
document.addEventListener('DOMContentLoaded', () => {
    renderTables();
    attachTOCHandlers();

```

### 2. Render Tables Function Flow
```
For each category:
  1. Filter tools for this category
  2. Determine which columns to include (dynamic filtering)
  3. Create category section with colored header (rounded corners)
  4. Create table with thead (dark gradient header)
  5. Build header row with filtered columns
  6. For each tool in category:
     a. Create row with category class (e.g., "disassembler-row")
     b. For each included column:
        - Get appropriate source URL based on column index
        - Get or create global source reference number
        - Track in local source refs
        - Apply cell styling (wrap in spans, not td classes)
        - Add cell content with superscript citation
  7. Append table to wrapper
  8. Create footnotes section
  9. Sort local refs by reference number
  10. Generate numbered list of sources
  11. Append section to container
```

After all tables rendered:
```javascript
document.getElementById('citationCount').textContent = Object.keys(globalSourceMap).length;
```

## Data Research Guidelines

### When Given a Topic

1. **Identify Categories** (aim for 5-12)
   - Group similar items together
   - Balance category sizes (avoid 1-2 item categories)
   - Use clear, descriptive names

2. **Select Comparison Criteria** (15-20 columns)
   - Start with universal criteria: Name, Cost, Platform, License
   - Add topic-specific technical features
   - Include integration/compatibility columns
   - Add support/community columns
   - Consider user experience factors

3. **Gather Data Points**
   - Research each item thoroughly
   - Use consistent value formats (✓/✗ for boolean, descriptive text for complex)
   - Mark uncertain data as "N/A" rather than guessing
   - Ensure data accuracy from official sources

4. **Collect Source URLs**
   - **6 URLs per item minimum**
   - Prioritize official documentation over third-party
   - Use specific subpages, not just homepage
   - Map URLs to column types:
     - [0] Main website/overview
     - [1] Pricing/licensing
     - [2] Platform/system requirements
     - [3] API/scripting documentation
     - [4] Feature list/capabilities
     - [5] Full documentation/manual

## Value Formatting Standards

### Boolean-style columns
- Use: `✓` for yes/supported (displays as simple black checkmark)
- Use: `✗` for no/unsupported (displays as black text)
- Use: `N/A` for not applicable (displays as black text)
- Use descriptive partials: "Via plugin", "Limited", "Basic", "Some support" (displays as black text)

### Text columns
- Keep concise (under 30 characters ideal)
- Use common abbreviations where clear
- Separate multiple values with "/"
- Use "+more" or "+" to indicate additional items

### Special Values
- "N/A" - Feature not applicable to this item type
- "Via X" - Available through another mechanism
- "Limited" - Partial or restricted support
- "Basic" - Minimal implementation
- "Advanced" - Comprehensive implementation

## Category Assignment Strategy

### Grouping Principles
1. **Functional similarity** - Tools serving similar purposes
2. **User persona** - Tools targeting same user types
3. **Technical approach** - Tools using similar methodologies
4. **Balanced distribution** - Aim for 3-15 items per category

### Category Key Format
- Lowercase
- No spaces (use underscores if needed)
- Short, memorable
- Examples: `disassembler`, `debugger`, `static_analysis`

## Common Pitfalls to Avoid

### ❌ Don't Do
- Use duplicate variable names (`tools`, `categories`, `sources`)
- Use `<a href="#...">` for TOC (causes external link warning)
- Include columns with all ✗ or N/A values
- Forget citations on any cell
- Use fewer than 6 source URLs per item
- Hard-code table HTML (must be JavaScript-generated)
- Forget to update citation count
- Use `localStorage` or `sessionStorage`
- **Apply badge classes to `<td>` elements** (causes cell merging)
- **Use colored badges or backgrounds** (not minimalist)

### ✅ Do
- Use unique variable names with suffixes (`toolsData`, `categoriesData`, `toolSources`)
- Use `<div data-target="...">` for TOC navigation
- Filter columns dynamically per category
- Add superscript to every cell
- Provide 6 specific source URLs per item
- Generate tables via JavaScript
- Update stats dynamically
- Keep all data in JavaScript variables
- **Wrap badge classes in `<span>` elements inside cells**
- **Use simple black checkmarks without colored backgrounds**
- **Add row classes for category border colors** (`${catKey}-row`)
- **Add 40px margin-top to all category sections**
